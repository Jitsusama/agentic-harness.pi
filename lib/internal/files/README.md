# Files

Reading files once and keeping their parse until they change, so a
reader asked often reads only what moved; where a file tool's path
points; and moving a file whole across volumes.

## Files

- **`errno.ts`**: what a failed read says of its path, nothing
  there, a fault of the moment, or something wrong with that path, so
  the readers of one folder keep or move on by one rule.
- **`file-reads.ts`**: what each file in a folder said when the
  process last read it, asked again only once the file changes, so a
  ledger asked at every conversation's start reads only what moved.
- **`folder-mirror.ts`**: a folder's files and their parses, kept for a
  host's synchronous readers and read again off the thread while asked,
  a file at a time as its watch names one, so a stalled disk holds none
  of its conversations; fed instead by what already follows the folder
  once for every process, where its kind names one, as presence names
  the mycelium node.
- **`move-file.ts`**: a file or a link moved whole, by rename, or by a
  copy renamed in beside its new place where a rename can't cross, as
  from outside a btrfs subvolume into it, so a carry's staging reaches a
  quest's scratch.
- **`stamped-read.ts`**: a file's parse kept while its inode, mtime
  and size say it is the same file, read on the thread or off it, for
  the mesh's presence listings.
- **`tool-path.ts`**: the file a read, write or edit names, as pi's
  file tools read its path, for the interceptors that look first.
